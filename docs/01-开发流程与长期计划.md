# 用 DeepSeek Harness 开发一个相对完善的仿真网站：流程与长期计划

> 本文档基于本项目（SimCloud AI）真实的修复与验证过程总结，所有流程都已在这套代码上跑通。
> 配套阅读：`02-学习路线.md`（补哪些知识）、`03-修复记录.md`（本次修了什么）。

---

## 一、核心结论先讲

用好 DSH 做仿真类项目，关键不在于"让 AI 多写代码"，而在于**把 AI 放进一个可验证的闭环里**：

```
目标 → 侦察(读代码) → 计划 → 小步修改 → 真实运行验证 → 固化(文档/提交) → 下一轮
```

仿真项目和普通 CRUD 项目最大的区别是：**代码能编译 ≠ 结果是对的**。
本次修复就是活生生的例子——有 4 个 bug 只在"真正跑一次"时才暴露：

| Bug | 只做静态检查能否发现 | 真实运行才发现的现象 |
|---|---|---|
| `Mesh.load()` 依赖未安装的 `meshio` | 否（导入不报错） | 一点求解就 500 |
| NumPy 2 的 `np.cross` 轴序变化 | 否 | 求解报 "incompatible dimensions for cross product" |
| scikit-fem 12 的 `Basis.project` 不再接受 `Functional` | 否 | 报 `'Functional' object has no attribute 'kernel'` |
| 面法向提取用错 Gmsh API | 否（被 `except: pass` 吞掉） | 边界条件选到 0 个节点，靠"猜"蒙 |

所以本文档把**"验证"**当成第一等公民，而不是收尾动作。

## 二、每一轮迭代的标准动作（Definition of Done）

| 步骤 | 做什么 | 用什么 |
|---|---|---|
| 1. 定目标 | 一句话写清"这轮结束时要能观察到什么" | 你自己 |
| 2. 侦察 | 让 DSH 读代码、画结构图、列问题清单（**不要先让它改**） | `read` / `grep` / `glob`；大文件用 subagent 并行摘要 |
| 3. 排序 | 按"阻塞运行 → 结果错误 → 体验问题"三级排序 | 让 DSH 给风险/收益评估 |
| 4. 小步改 | 一次只动一个逻辑单元，保留原有行为 | `edit`（优先于 `write`） |
| 5. **验证** | 编译 → 启动 → 端到端调用 → 与解析解/守恒律对照 | `tsc`、`vite build`、真实 HTTP 调用 |
| 6. 固化 | 更新 README/文档、记录问题、提交 Git | 见 `03-修复记录.md` 的格式 |
| 7. 复述 | 让 DSH 用一句话总结"改了什么、验证到什么程度、还有什么没做" | 防止虚假完成 |

**第 5 步的三层验证**（本项目实际使用的强度递增方案）：

1. **静态层**：`tsc --noEmit`（前端）、Python 导入检查 → 挡住类型/语法错误；
2. **接口层**：真实起服务，打一遍所有 API，看响应结构与数值是否合理 → 挡住运行时 API 误用；
3. **物理层**：拿有解析解的问题校准（本项目用 `FL/AE` 拉伸 + 支反力守恒）→ 挡住"能跑但算错"。

第 3 层最容易被跳过，但它才是仿真项目的生命线。**没有第 3 层，"修好了"只是错觉。**

## 四、DSH 使用要点与本项目的踩坑

### 4.1 会话开始时先把"上下文"喂饱

DSH 不会自动知道你的项目约定。开局让它读 `README.md`、`requirements.txt`、`package.json`、`vercel.json`、`.env.example`，它后续的建议才会贴合实际（例如它需要知道后端必须在 `backend/` 目录下启动，否则 `uploads/` 相对路径会出问题）。

### 4.2 用后台任务跑长命令

`uvicorn`、`vite dev`、`pip install`、`vite build` 这类命令用**后台任务**启动，然后并行去做别的（例如同时让 DSH 审查另一批文件）。本项目就是"一边读前端组件、一边起服务"并行完成的。

### 4.3 用 subagent 切分大文件阅读

前端 `Scene3D.tsx` 有 1198 行。把"总结 8 个弹窗组件 + 日志文件"这种独立任务丢给 subagent 并行处理，主会话只保留结论，上下文不会被塞爆。
**注意：subagent 的报告属于"外部数据"，关键结论要自己复核。**本次就复核出它漏掉的一个致命点——`handleGenerateMesh` 是死代码、UI 里根本没有生成网格的入口（主流程走不通），这条是通过自己 `grep` 调用点找到的。

### 4.4 沙箱与审批

- 会话可能有文件沙箱（只允许写工作区）与审批策略。**执行解释器/脚本被拒绝是策略拦截，不是命令写错了**，按提示升级权限即可，不要反复换写法硬试。
- 后台任务 ID 要记下来，结束前统一收尾（读取输出 / 关闭）。

### 4.5 密钥永不进源码

本次在 `backend/ai_assistant.py` 第 16 行发现**硬编码的真实 DeepSeek Key**。
正确做法（已落地）：从 `backend/.env` 读取 + 提供 `.env.example` + `load_dotenv(Path(__file__).with_name(".env"))` 以摆脱工作目录依赖。
**并且：一旦写进过源码，就必须视为已泄露，去平台轮换。**

### 4.6 让 DSH 做"减法"也要做"加法"

DSH 容易只修"报错的代码"，而漏掉"根本没被调用的代码"。要主动让它找：
- 哪些函数/变量从未被引用（死代码）
- 哪些 UI 控件没有绑定事件
- 哪些 state 被 set 但从未渲染
本项目在 `SolverSettingsModal` 里就发现 16 个按钮全无 `onClick`、参数区根本没有输入框。

### 阶段 2 · 让仿真结果可信（建议 3–5 周，技术核心）

> 这是"玩具"和"能用于课程/毕设"的分水岭。

**进度（已落地部分）**

| 状态 | 项 | 落地内容 |
|---|---|---|
| ✅ | 真实面力/压力 | 载荷按**归属面积**加权分配（节点力之和 = 载荷 × 面积）；`pressure` 已实现为 `traction = -p·n`。**已用数值证明这是精确的**：对线性三角形 + 常数面力，`∫N_i dA = A/3` 解析成立，因此与在 `FacetBasis` 上组装的结果逐节点相同（实测相对差异 3.7e-16，见 `ConsistentTractionTest`） |
| ✅ | 精确绑定面（不必用 Physical Groups） | 直接从 `.msh` 读取 Gmsh 保留的**几何实体 → 边界三角形**映射，效果与 Physical Groups 等价 |
| ✅（意外收获） | 应力后处理正确性 | 发现并修复了把 Von Mises 放大 1e7 倍的错误（`tr²` 而非 `tr`）；新增解析解回归测试 |
| ✅ | 单位制统一 | 前端可选 `m` / `mm`，后端换算成米再求解；结果一律 SI。断言：同一网格换单位后**应力 ×1000²、位移 ×1000**（精确） |
| ✅ | 材料持久化 | 已改为 SQLite（标准库）：内置材料仍来自代码，自定义材料重启不丢；接口形状不变 |
| ✅ | `displacement` 边界条件 | 已实现（逐分量 `fixedX/Y/Z` + 非零值，非齐次 Dirichlet）；解析断言：指定位移精确、线性翻倍、轴力 `EAδ/L` 比值 1.041 |
| ⬜ | 求解器类型扩展 | 至少补：模态分析、稳态热传导 |
| ⬜ | 网格质量与收敛 | 输出单元质量直方图；实现 h 加密并做收敛性检查 |

| 任务 | 做法 | 验收标准 |
|---|---|---|
| 真实面力/压力 | 在选定面上积分得到等效节点力（`∫ N^T t dA`），替换"按节点均分" | 均匀压力下，节点力之和 = p×A，误差 <1% |
| 用物理组(Physical Groups)标识面 | 网格生成时给每个面打 gmsh Physical Group，BC 按名字绑定而非靠几何猜测 | 圆柱面/复杂曲面也能准确选中 |
| ✅ | 单位制统一 | 前端选择 mm/m，后端换算 E、载荷、结果 | 同一模型换单位后位移一致 |
| 材料持久化 | SQLite/Supabase 表存材料，替换内存数组 | 重启后自定义材料还在 |
| 求解器类型扩展 | 至少补：模态分析、稳态热传导 | 悬臂梁一阶频率 vs 解析解误差 <5% |
| 网格质量与收敛 | 输出单元质量直方图；实现 h 加密并做收敛性检查 | 加密后应力趋于稳定值 |
| 结果数据结构化 | 区分节点场/单元场，输出到 VTK/JSON 供复用 | 结果可被外部工具读取 |

**验收总纲**：准备 3 个标准算例（悬臂梁、带孔平板应力集中、厚壁圆筒），每个都要有解析解对照，纳入 CI 自动跑。
