# 如何扩展求解器（给下一个人）

> 这份文档解决一个问题：**别人想给这个项目加功能时，知道该动哪里、以及怎么证明自己没改错。**
> 本项目最大的坑不是"不会写代码"，而是"改完不知道结果对不对"——历史上就漏掉过一个把
> 应力放大 1e7 倍的错误（见 `03-修复记录.md` 第五节）。所以本文每条路径都配了验证方式。

---

## 1. 求解器的数据流

`POST /api/solve` 进来后依次做六件事（都在 `backend/solver.py` 的 `solve_simulation`）：

| 步骤 | 做什么 | 关键代码 |
|---|---|---|
| 1 | 校验文件名、查材料 | `resolve_upload_path()`、`MATERIALS_DB` |
| 2 | 读网格 | `load_tet_mesh_from_msh()` → 返回 `(MeshTet, {面tag: 边界三角形})` |
| 3 | 建基函数与刚度阵 | `Basis(mesh, ElementVectorH1(ElementTetP1()))`、`asm(linear_elasticity(lam, mu))` |
| 4 | **施加边界条件** | 定位节点 → 按 `bc.type` 分派 → 写 `f` / `prescribed_dofs` / `warnings` |
| 5 | 求解 | `solve(*condense(K, f, x=prescribed_values, D=D))` |
| 6 | 后处理 | 支反力 `K@u - f`；Von Mises 在积分点求值后 L2 投影到 P1 |

第 4 步是**最常被扩展**的地方；第 6 步是**最容易算错**的地方。

### 1.1 边界条件是怎么"定位节点"的

优先走**精确路径**：`face_triangles[entityIndex]` 是 Gmsh 在 `.msh` 里保留的
「几何面 → 边界三角形」映射，直接给出该面的节点，并按**归属面积**加权
（`nodal_tributary_areas`：线性三角形每个顶点分得面积 1/3，故节点力之和 = 载荷 × 面积）。

拿不到映射时才退化为几何搜索（点到平面距离 → 包围盒启发式），并打 debug 日志。

## 2. 新增一种边界条件类型（完整范例）

以本项目的 `displacement`（强制位移）为例——它原本被求解器**完全忽略**，
用户加了它只会看到"求解成功、结果为零"。下面是当时实际做的四步：

### 第 1 步：模型里必须有承载字段

`backend/constraints.py`：

```python
class BoundaryCondition(BaseModel):
    model_config = ConfigDict(extra="forbid")   # ← 关键：不让字段被静默丢弃
    type: Literal["fixed", "displacement", "force", "pressure", "temperature"]
    displacement: Optional[Union[Vector3, dict, List[float]]] = None
    fixedX: Optional[bool] = None               # 逐分量开关
    fixedY: Optional[bool] = None
    fixedZ: Optional[bool] = None
```

> ⚠️ **这一步最容易漏**。`pressure` 当初就是"`type` 里有、字段里没有"，
> Pydantic 默认 `extra="ignore"` 会把值悄悄扔掉，于是后端永远拿到 0。
> 现在开了 `extra="forbid"`，字段对不上会直接 422。

### 第 2 步：加入支持列表并实现分派

`backend/solver.py`：

```python
supported_types = {"fixed", "displacement", "force", "pressure"}
...
elif bc.type == "displacement":
    values = _parse_displacement(bc)            # dict / Vector3 / list 统一成 (ux,uy,uz)
    flags = (bc.fixedX, bc.fixedY, bc.fixedZ)
    if all(f is None for f in flags):           # 与前端默认值一致：全约束
        flags = (True, True, True)
    for component in (c for c in range(3) if flags[c]):
        for node_idx in target_nodes_indices:
            prescribed_dofs[int(basis_vec.nodal_dofs[component][node_idx])] = float(values[component])
```

**不支持的旧类型不要静默丢掉**——写进 `solver_warnings`，随响应返回，前端会弹黄色横幅。

### 第 3 步：非齐次Dirichlet 要用 `condense(x=...)`

零位移（固定约束）和非零位移（强制位移）**走的是同一套** `prescribed_dofs`，
只是值不同：

```python
prescribed_values = np.zeros(basis_vec.N)
for dof, value in prescribed_dofs.items():
    prescribed_values[dof] = value
u = solve(*condense(K, f, x=prescribed_values, D=D))
```

要点（踩过的坑）：`x` 是**全长向量**，只有 `x[D]` 会被用到；
内部等价于 `b_I - A_ID @ x_D`（见 `skfem.utils.condense` 源码）。
另外 `D` 为空时要保留"自动约束 3 个远端点"的兜底，否则矩阵奇异。

### 第 4 步：前端补齐 UI

- `frontend/components/BoundaryConditionSelector.tsx`：该类型的输入控件；
- `frontend/types.ts`：联合类型；
- 若前端有字段名与后端不一致，**以 `tests/test_solver_regression.py` 的
  `BoundaryConditionContractTest` 为准**——它按前端实际发送的形状构造 5 种边界条件，
  字段漂移会立刻失败。

### 第 5 步（不可省）：加验证

见第 5 节的判据表。强制位移用的是"精确性 + 线性性 + 物理量级"三层断言。

## 3. 新增一种分析类型（例如稳态热传导）

比新增边界条件大，但路径清晰。需要动的地方：

| 位置 | 改动 |
|---|---|
| `backend/materials.py` | 加材料属性（例如热导率 `thermalConductivity`；**记得同时改 `material_store.py` 的表结构与迁移**，否则老库打不开） |
| 新建 `backend/thermal_solver.py`（本项目已落地为 `thermal.py`） | 新的弱形式装配：`asm(laplace(k), basis)`，边界条件改为"给定温度" |
| `backend/main.py` | 挂载新路由 |
| `backend/jobs.py` | 加一个 `POST /api/jobs/<kind>`（长任务必须能异步跑） |
| `backend/fe_utils.py` | 直接复用网格读取与**面→节点定位**，不要另写一套 |
| `frontend/components/SolverSettingsModal.tsx` | `ANALYSIS_TYPES` 里已列出 4 种；把 "Heat Transfer" 接到新端点 |
| `frontend/components/Workbench.tsx` | 求解时按 `solverType` 选端点 |
| 测试 | 解析解：一维杆两端定温 → 线性温度分布、热流 `q = k·ΔT/L` |

> 实战经验（来自本项目的热传导实现）：线性单元能**精确重现**线性解，因此
> "两端定温 + 其余面绝热"的一维导热算例可以把容差卡到机器精度（温度 1e-9、
> 热流相对 1e-6）。挑算例时优先找这种"有限元恰好精确"的情形。

**建议**：先只做"能算对"的最小闭环（一个解析算例 + 一条 API + 测试），
再补 UI。历史上一次性改太多地方，验证不过来就容易被"看起来成功了"骗过去。

## 4. 性能与数值上的扩展点

| 想做的事 | 从哪里下手 |
|---|---|
| 更大的网格 | `condense` 换迭代求解器（CG + 预处理），现在用的是稀疏直接法 |
| 面载荷 | 现在是"三角形面积 1/3 分给顶点"，**对线性三角形 + 常数面力这是精确解**（`∫N_i dA = A/3`），已用 `FacetBasis` 精确积分对照验证（相对差异 3.7e-16）。若将来改用高阶单元或非均匀面力，则需要改为在面基函数上组装真实面载荷向量 |
| 单元阶次 | `ElementTetP1` → `ElementTetP2`（同时要改网格读取里的单元类型映射，现在只识别 gmsh 的 4 节点四面体） |
| 非线性 / 动力学 | 需要引入时间步或牛顿迭代；建议先把 `solve_simulation` 拆成"装配 / 施加 / 求解 / 后处理"四个函数再动 |
| 长任务 | 网格与求解目前是同步 HTTP，大模型会超时；阶段 3 计划改为后台任务 + 进度 |

## 6. 已知陷阱清单

| 陷阱 | 说明 |
|---|---|
| gmsh 线程约束 | `gmsh.initialize()` / `finalize()` 会调用 `signal.signal()`，而**信号处理只能在主线程设置**。因此不能在工作线程里 initialize/finalize。本项目由 `gmsh_session.py` 在主线程初始化一次、进程内复用，每次操作前 `gmsh.clear()`；所有 gmsh 操作都在 `jobs.py` 的单线程工作器里排队 |
| SQLite 连接 | `with sqlite3.connect(...) as conn` **只提交事务、不关闭连接**，用在循环里会泄漏句柄并锁住数据库文件（Windows 上连删除都失败）。用 `material_store._cursor()` 那种写法：`try: with connection: yield ... finally: connection.close()` |
| Pydantic 静默丢字段 | 默认 `extra="ignore"`。新增字段一定要同时改模型，本项目已开 `extra="forbid"` |
| `eye(w, n)` 的语义 | 它**把 w 放到对角线**，所以偏应力是 `s - (1/3)*eye(trace(s), 3)`，**不要再乘一次 trace**（乘了就是 tr²，应力会大出几个数量级） |
| NumPy 2 的 `np.cross` | 轴约定改成了**末轴**；`(3, N)` 形状必须转置成 `(N, 3)` |
| skfem 版本差异 | 12.x 里 `Basis.project()` 不接受 `Functional`；`Mesh.load()` 依赖 meshio（本项目改用 Gmsh 直接读） |
| gmsh 单位 | 坐标来自 CAD，**通常是毫米**。现在由 `length_unit` 显式声明并在求解前换算成米，结果一律 SI（位移 m、应力 Pa）。新增涉及长度量纲的代码时，请确认它用的是**换算后**的坐标（`mesh.p`），面元数据里的 `center` 仍是**输入单位**，需要乘 `length_scale` |
| 绝对容差 | 单位换算会暴露所有写死的容差：原先"点到平面距离 < 1e-2"在毫米模型上会把整个模型选进来。现在一律用**相对模型尺度**（`model_span * 1e-3`） |
| Windows 控制台编码 | GBK 代码页下打印 emoji 会抛 `UnicodeEncodeError`；任务脚本已设 `errors="replace"`，新代码请避免 emoji |
| PowerShell 读写 UTF-8 源文件 | `Get-Content` 在 Windows PowerShell 5.1 下**默认按 ANSI 解码**。对无 BOM 的 UTF-8 源文件用 `Get-Content ... \| Set-Content -Encoding UTF8` 会把中文**二次编码**成乱码（本项目真踩过，靠 git 恢复）。改文件请用编辑工具，或显式 `Get-Content -Encoding UTF8` |
| `.ps1` 需要 BOM | 无 BOM 的 UTF-8 会让 PowerShell 5.1 按 ANSI 解析中文而语法报错（`.editorconfig` 已声明） |
| `python` 可能是 Store 桩 | Windows 上 `python` 常是"应用执行别名"，调用无输出也不报错；用 `py -3` 或 venv 里的解释器 |

## 7. 提交前检查清单

```bash
# 1) 回归测试（不需要服务，含解析解与物理校准）
python3 tools/tasks.py test

# 2) 端到端（需要服务）
python3 tools/tasks.py dev --detach
python3 tools/tasks.py verify
python3 tools/tasks.py stop

# 3) 改了前端还要
python3 tools/tasks.py build
```

- [ ] 新增/修改的物理行为有**解析解或守恒律**断言
- [ ] 不支持的输入会**大声失败**（4xx / warnings），而不是静默算错
- [ ] 新增的开发任务写进 `tools/tasks.py`，不要在 `scripts/*.ps1` 里另写一套
